## [S3.3] No-streaming guard

**Epic:** E3 (Two-Message Protocol) · **Priority:** P1 · **Repo:** antariksh · **Issue:** #14
**Workflow:** `ds:ready → ds:done → claude:review → chairman:approve` (PRD §5)

### Goal
Architecturally forbid intra-session MTM messages. Across a full session, exactly **two**
broadcast calls fire (start + end); anything else is a bug.

### Context / why
ABOUTME §3-4: the session-brain must get no minute-by-minute updates — that's the override
window. A test must enforce the invariant so a future change can't silently re-introduce streaming.

### Files to change / exercise (verified 2026-06-13)
- `antariksh/crews/telegram_reporter.py` (`:12`, `:54`, `:69`) — the broadcast surface to count.
- ADD: `antariksh/tests/test_two_message_invariant.py` — wraps/mocks the broadcast fn and
  asserts call-count == 2 over a simulated session (errors use a separate channel, not counted).
