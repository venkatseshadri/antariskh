## [S4.2] Findings → triage workflow

**Epic:** E4 (Code Conformance Audit Loop) · **Priority:** P1 · **Repo:** antariksh · **Issue:** #16
**Workflow:** `ds:ready → ds:done → claude:review → chairman:approve` (PRD §5)

### Goal
A human/DS-gated step that turns audit findings into E5 stories — **without** auto-creating or
auto-deleting anything. Removal candidates only become real work after Chairman approval.

### Context / why
PRD §E4 + CODE_AUDIT_LOOP.md §5: the audit loop proposes; a separate triage step groups new
findings and emits ready-to-file issue bodies. This keeps the propose-only guarantee intact.

### Files to change / add (verified 2026-06-13)
- READ: `antariksh/data/code_audit.jsonl` (append-only findings ledger),
  `antariksh/docs/REVIEW_FINDINGS.md` (latest sweep).
- ADD: `antariksh/ralph/triage_findings.py --since <ts>` — lists new findings grouped by
  severity; for each `remove_candidate`/defect emits an issue-ready markdown body
  (does **not** call `gh issue create`).

### Implementation steps
1. Parse `code_audit.jsonl` since a timestamp; dedupe to latest verdict per path.
2. Group by severity; for each removal candidate / high-severity finding, render an issue body
   (title, finding id, file, rubric dims, suggested action) to stdout or `docs/triage/`.
3. Print a one-line summary; **never** auto-create issues or remove files.
