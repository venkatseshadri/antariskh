**Epic:** E6 (Dev/Prod Isolation) · **Priority:** P0 (unblocks isolated validation) · **Repo:** antariksh + brahmand · **Issue:** #22
**Workflow:** `ds:ready → ds:done → claude:review → chairman:approve` (PRD §5)

### Goal
Every data path resolves through `config/db_paths.py` / `BRAHMAND_SANDBOX`, so a dev/test run
**never** reads or writes prod data. Today ~15 files hardcode the absolute prod path
`/home/trading_ceo/python-trader/varaha/data/...` (and one writes prod `capture_nifty.sqlite`),
which makes the PORCUPINE harness **prod-coupled** — `lifecycle`/`tp_hit`/`floor` fail right now
because `position_manager`'s research path hits the *prod* DuckDB lock.

### Context / why
Audit 2026-06-14 (E6). `BRAHMAND_SANDBOX` already redirects core paths; these do NOT honor it.
This story is the **prerequisite for trustworthy 24/7 validation** — without it, the dev loop's
tests reach prod. Also advances S0.3 (single source of data paths).
